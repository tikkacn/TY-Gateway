# OEC 一键安装 Pilot：新一轮实机验收

更新：2026-10-01。候选 v0.8.7；代码检查不代替真机验收，正式稳定版必须在实机通过后决定。

本轮只验管理地址修复：在已安装 OEC 升级后，保留主路由 DHCP，关闭 OEC DHCP/LAN DNS，再将 .164 改为 .9、通过新地址登录确认。成功后再考虑 DHCP 接管；不要为此重刷或重置注册。失败回传事务和 helper 日志。见 [步骤与证据](NETWORK-ADDRESS.md)。以下是完整首装验收计划，不要求为本轮扩展测试范围。

## 新一轮起点

两台旧设备及 MAC 预登记/SN/FRP 已按用户要求清除。用户重刷、恢复各自真实 MAC 后重新预登记。首台应得到设备编号 1 和 FRP 22000，第二台应为 2 和 22001。不能复用 Armbian 镜像的重复 MAC 或旧凭据。

保留共享订阅源和通用规则设置；不会删除旧阶段 Release，除非用户明确要求。Pilot 不上传 R2，也不干扰 Guide 分发。

## 顺序与通过条件

| 阶段 | 只检查这些事项 | 当前证据 |
| --- | --- | --- |
| 1. 一键首装 | 自动补齐 DAE/运行依赖/程序/服务；设备码和接口正确；默认不接管 DHCP/DNS/代理；中断重跑不重复身份或覆盖设置 | 安装器已有恢复/幂等逻辑，新一轮全新系统待验 |
| 2. 自动注册与 FRP | 预登记真实 MAC；自动身份落盘；设备编号与专属端口正确；公网 SSH 握手；重启后恢复且不产生新设备 | 上一轮用户确认注册与 SSH 握手通过；本轮重新验证 |
| 3. 订阅与规则 | 管理员绑定后正常下发；无订阅也有合法 DAE 配置；DAE 解析后的节点清单排除大小写 IPV6 名称；分流选择与清单一致 | 用户上一轮总体认可，新一轮待核对；订阅统计不再累加用户节点数 |
| 4. 开关与真实链路 | 关闭时直连、重启仍关闭；开启时 DAE 代理并命中指定规则、重启仍开启；验证出口 IP 和保护/设备绕过规则 | 必须从局域网客户设备实测，不能仅看重载成功 |
| 5. 失败保留与恢复 | 更新失败保留上一版规则/节点；短时断网后注册/同步/FRP重试；接口重连和重启后转发参数符合设计 | 不主动破坏主路由或扩大故障范围，用户配合最小验证 |
| 6. 更新与配置 | 本地离线上传验签；在线升级保留配置；管理员受控回退、用户不可降级；导出/导入/重置不改变注册和维护通道 | 功能已实现，跨版本真实升级/回退仍待验 |

先在一台按顺序走通，第二台用于验证独立身份与分配；失败停在对应阶段，保留日志及上一有效配置，不再次无目的刷机。首次联网需要主路由 DHCP 开着；之后如接管 DHCP，用户确认并明确切换。

## 必须区分

SSH 密码提示证明 FRP→设备 SSH 握手，不证明 root 登录。DAE 校验/服务 active 不证明客户流量按规则走。已验证节点列表不等于当前实际出口。固定节点不自动具备故障转移；应显式选择故障转移并配置备用。

已安装设备的离线包升级不依赖 GitHub；全新 Armbian 首装仍需系统依赖网络源。v0.8.6 已实现测速颜色与自定义 URL：第 4 阶段增加一次真实测速、保存地址和日志恢复检查，不扩大硬件/故障测试范围。[详细边界](NODE-LATENCY.md)。

本轮不测试所有 ARM 板型，不升级系统/内核，不自动调整真实 MAC，不改变另一项目分发。测试范围需围绕本轮目标，避免盲目消耗时间。

管理员反激活已加入云端，与 v0.8.6 及后续设备包兼容。需要重刷测试机时可在“设备中心 → 查看详情 → 设备反激活”撤销旧身份，保留 MAC/当前基础方案/订阅预绑定，等待旧 FRP 隧道关闭，再重刷首装。旧程序和普通升级不会自动重新认领，编号不会因单台反激活归零。此项实机断链/重刷验证由用户明确选择设备后进行，不用于随意重置已通过的测试；见 [反激活说明](DEVICE-DEACTIVATION.md)。
