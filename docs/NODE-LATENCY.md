# 本地节点延迟测速

v0.8.6 Pilot 的入口是“代理与规则 → 网站分流 → 节点延迟测速”。显示经过代理节点的 HTTP 延迟，不是带宽，也不是网站策略当前实际出口。

- 内置 Cloudflare、Google、Microsoft，也可保存自定义公开 HTTP/HTTPS 地址。仅 80/443，拒绝凭据、内网/保留地址和配置分隔符。域名解析到公开 IPv4 后固定地址，原域名仍用于 Host/SNI；域名地址迁移时重新保存即可重新解析。
- 地址保存在 Agent 私有 `node-check.json`，经受控策略写入 dae `tcp_check_url`，方法 HEAD。云端同步不覆盖用户地址，升级/重启保留。配置导出包含地址、不包含测量历史；旧备份没有此字段则保留现值；用户重置恢复默认地址、清除旧结果。
- 手动测速只允许本地开关开启、已应用代理策略、dae 运行且本机有验证节点。不会为测速开启代理。配置同步/测速执行时稍后重试，测速间隔至少一分钟。
- Helper 短时开启 dae DEBUG，读取原生 `Connectivity Check` 的 TCP/IPv4 结果，最多观察 40 秒，再恢复原始配置及日志级别。只返回名称、状态、延迟、时间，不返回原始错误或流量日志。由本机验证节点匹配 ID，不猜测数值。
- 绿：<150 ms；黄：150–300 ms；红：更高或连接失败；灰：未观测/未测速/超过五分钟。真实 0 ms 显示 `<1 ms`，缺数据绝不记零。换地址清除旧结果，测速失败保留上一批。
- DEBUG 会短时重载 dae，并留下系统 journal 记录（可能含流量元数据），按系统日志策略保留；不会清空整机 journal。正常结束/失败恢复原日志配置，掉电后 helper 启动先恢复。恢复失败保留 root-only 标记，不报告成功；外部同时改配置时拒绝覆盖。

接口经本地登录和变更来源校验：GET `/api/customer/speed-test`，POST `/api/customer/speed-test/settings`（`url`），POST `/api/customer/speed-test/run`。地址/结果不写云端数据库，不开放修改管理或 FRP 凭据。

依据固定 dae v2.1.1 的健康检查和日志，并非虚构运行时 API。上游改变格式时可能显示未测速，需要维护 parser，不把缺失当成功/失败。[上游配置示例](https://github.com/daeuniverse/dae/blob/v2.1.1/example.dae)。

针对性本地检查及 ARM64 构建不代替真机验收。OEC 需确认：自定义地址实际更新配置、点击产生真实延迟、失败/未观测区分、代理关闭不被测速启动、测速结束日志恢复、重启与导出/导入/重置行为。
